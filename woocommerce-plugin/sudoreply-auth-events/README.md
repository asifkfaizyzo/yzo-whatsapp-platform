# SudoReply WooCommerce Auth Events

This plugin sends signed events for WooCommerce customer logins, password-reset requests, and checkout cart updates to SudoReply. It never sends a password. It sends the reset URL generated by WordPress/WooCommerce, so the store's own reset token, expiry, and one-use behavior remain in effect. Cart events are sent after a phone number is entered on checkout; cart contents are saved briefly so the recovery link can restore the items before returning to checkout.

## Install and configure

1. Install and activate this directory as a WordPress plugin.
2. In SudoReply, connect the WooCommerce store and obtain the auth webhook configuration with the tenant owner's access token:

   ```http
   GET /api2/woocommerce/auth-webhook-config
   Authorization: Bearer <tenant-owner-access-token>
   ```

3. In SudoReply, open WooCommerce integration settings and show the cart recovery plugin setup values.
4. In WordPress, open **Settings → SudoReply Auth Events**. Enter the cart recovery endpoint, tenant ID, and signing secret from SudoReply. The authentication-event endpoint is separate and can remain configured as before.
5. Leave the verified-phone meta key blank until the store has a real phone ownership verification process. If the store has one, configure its user-meta key and the exact value that means verified.
6. For development, set backend `MOCK_WHATSAPP=true` and `WHATSAPP_DEV_RECIPIENT` to the verified test number. Login events and reset-link processing are simulated; reset emails are not suppressed in mock mode.
7. For live sending, set `MOCK_WHATSAPP=false`, connect the tenant's WhatsApp sender, and configure `WC_LOGIN_ALERT_TEMPLATE` and `WC_PASSWORD_RESET_TEMPLATE` to the exact approved template names stored for that tenant. Keep the customer's verified phone meta configured.

## Cart recovery events

The plugin captures a cart when a shopper updates checkout after entering a valid billing phone number. It sends the cart contents, total, product image URLs, and a signed seven-day recovery link. WooCommerce's order-created webhook includes the recovery ID so pending reminder jobs are cancelled after checkout is completed. SudoReply schedules 1-hour, 24-hour, and 48-hour reminders according to the tenant's WooCommerce recovery settings.

The cart recovery link uses a random, one-time token stored as a WordPress transient. Clicking it restores the saved products to the shopper's cart and redirects to checkout. The transient expires after seven days.

In development, WooCommerce reminders honor `SHOPIFY_OVERRIDE_PHONE_IN_DEV=true` and send to `META_TEST_PHONE` instead of the checkout phone, matching Shopify's test-recipient behavior. The override is not used in production.

## Approved template parameters

- Login template body: `{{1}}` is the customer name; `{{2}}` is the login time. Either may be omitted.
- Reset template body: `{{1}}` is the customer name; `{{2}}` is the reset URL. A template with a dynamic URL button may instead use `{{1}}` for the URL suffix, provided the WooCommerce reset URL begins with the approved button URL prefix.
- Templates with non-sequential placeholders or unsupported parameter counts are rejected rather than sent with incorrect substitutions.

The plugin suppresses WooCommerce's reset email only after Meta accepts the live WhatsApp template request. If the webhook or Meta request fails synchronously, the email remains enabled. Mock delivery deliberately does not suppress the email. A later WhatsApp delivery failure is asynchronous and is not currently wired to resend the email.

## Development versus live

Mock mode verifies that login/reset hooks send signed requests and the backend verifies and routes the events without calling Meta. It does not exercise approved-template substitution or real delivery; template mapping is covered by backend unit tests. Production uses the same signed endpoint and sender code path, but requires Meta-approved templates and a verified customer phone number. Secrets and template names are not stored in this plugin's source.
